# 行程详情 V2 与高德地图接入设计规格

## 1. 背景与目标

本项目已经具备本地行程生成、预览确认、行程库、单地点增删改、预算与交通住宿管理，也已经预留高德地图后端代理、地点搜索、地图标点和相邻地点路线计算。本阶段要把这些能力连接为成熟的行程编辑闭环：用户保存行程后，可以在详情页直观调整顺序和日期，使用真实地点完成定位，在地图上查看安排并计算真实路线，同时让修改可靠保存、可撤销、失败可恢复。

成功标准：

- 高德 Web 服务 Key、JS API Key 和安全密钥通过本地后端安全配置生效，服务密钥不进入前端包；
- 用户能够搜索真实地点、选择 POI、保存地址、GCJ-02 坐标和城市编码；
- 每日地点可排序、同城跨日移动、复制整天安排和清空普通安排；
- 排序和移动后自动重新编排当天时间，并清除已失效的交通估算；
- 桌面端支持拖拽，键盘和移动端始终提供等价的按钮操作；
- 日程修改自动保存，并保留手动重试与多步撤销；
- 地图、搜索或路线不可用时不阻断手动编辑，不显示虚假地图或路线；
- 现有预算、交通住宿、行程库和创建流程继续工作；
- 本阶段只在本地联调，不部署 Netlify。

## 2. 范围

### 2.1 本阶段包含

- 本地 `.env.local` 高德配置与后端实网状态验证；
- 真实地点搜索、真实底图、标点、相邻地点步行/驾车/公交路线；
- 单日地点拖拽排序、上移、下移；
- 同一目的城市的跨日移动；
- 整天复制到同城目标日、清空当天普通安排；
- 时间自动重排与精确时间/停留时长编辑；
- 时间重叠、结束过晚、安排过密、待定位地点提示；
- 防抖自动保存、保存失败重试、多步撤销；
- 桌面与移动响应式交互、单元/组件/API/真实浏览器验收。

### 2.2 明确不包含

- 跨城市移动已定位 POI；需要跨城时应在目标城市重新搜索并添加；
- 自动选择最优路线或自动重排整趟行程；
- 把高德路线结果永久缓存为长期导航数据；
- 实时路况、未来班次、开放时间、票价或库存保证；
- 酒店、机票、火车票搜索或支付；
- 账号、云同步、多人协作和分享链接；
- 首页改版和 Netlify 部署。

## 3. 安全与配置

使用现有 Python FastAPI 后端作为安全边界：

- `AMAP_WEB_SERVICE_KEY` 仅用于后端地点搜索和路线请求；
- `AMAP_JS_SECURITY_CODE` 仅由后端受限代理使用；
- `AMAP_JS_KEY` 可以由 `/api/maps/status` 返回给浏览器，用于加载 JS API；
- 三个值写入被 Git 忽略的 `apps/api/.env.local`，不得进入源码、测试快照、日志、文档或前端环境变量；
- 前端本地开发通过 `apps/web/.env.local` 的 `NEXT_PUBLIC_API_BASE_URL=http://127.0.0.1:8000` 连接后端；
- 生产环境必须使用 HTTPS 后端、域名白名单、服务器 IP 限制和共享限流，本阶段不声称已完成生产授权；
- 本次聊天截图中的密钥只能用于本地联调，正式上线前必须轮换。

后端继续限制代理路径，只允许高德地图样式请求；地点搜索和路线计算统一经过已校验的业务接口。接口返回错误时使用可操作中文信息，不回退为演示数据。

## 4. 日程编辑模型

### 4.1 排序与时间重排

新增纯函数编辑能力，不把拖拽逻辑直接写进页面：

```ts
type ScheduleMove = {
  fromDayIndex: number;
  fromItemIndex: number;
  toDayIndex: number;
  toItemIndex: number;
};

function moveScheduleItem(itinerary: Itinerary, move: ScheduleMove): Itinerary;
function normalizeDayTimes(itinerary: Itinerary, dayIndex: number, startTime?: string): Itinerary;
function duplicateDayItems(itinerary: Itinerary, fromDayIndex: number, toDayIndex: number): Itinerary;
function clearDayItems(itinerary: Itinerary, dayIndex: number): Itinerary;
```

规则：

- 同日排序允许任意地点，包括锁定的必去地点；锁定只禁止删除和替换，不禁止改变顺序；
- 跨日移动只允许来源日和目标日城市相同；
- 同日拖到原位置或非法索引返回原对象，不产生保存记录；
- 排序、跨日移动、复制或清空后，从当天原第一项开始时间（空日使用 09:00）依次排程，地点之间保留 30 分钟缓冲；
- 每项停留时长保持不变，结束时间由开始时间加停留时长计算；
- 受影响日期的 `transport` 和 `transport_minutes` 清空，因为顺序改变后旧估算失效；
- 复制整天时目标日必须同城，复制的普通与必去标记保持不变，但同一目标日已存在的同名 POI 或同名手动地点不重复加入；
- 清空当天时只移除非锁定安排，保留必去地点并重新排程；
- 排序和跨日移动不改变计划支出；清空当天按实际移除地点扣减计划支出；复制只对去重后实际新增的地点按现有整团预算口径增加计划支出。

### 4.2 精确时间与停留时长

选中地点后提供轻量编辑：开始时间、停留分钟。保存后更新 `end_time` 并按开始时间重新排序，但不自动移动其他地点；若产生重叠，页面立即显示冲突提示。这样用户可以选择“自动重新排程”或保留有意的并行安排。

安排不得跨越午夜。无效时间、非正整数停留时长或结束时间超过 23:59 时阻止提交并显示字段级错误。

### 4.3 日程诊断

新增纯函数诊断结果：

```ts
type ScheduleIssue = {
  kind: "overlap" | "late" | "dense" | "unlocated";
  message: string;
  itemIndexes: number[];
};

function analyzeDaySchedule(day: ItineraryDay): ScheduleIssue[];
```

- `overlap`：现有时间区间相交；
- `late`：最后一项在 19:00 后结束；
- `dense`：轻松超过 2 项、适中超过 3 项、紧凑超过 4 项；
- `unlocated`：坐标为 `[0,0]` 或没有 `location_source: "amap"`；
- 提示不阻断保存；未知地点绝不使用目录坐标冒充高德定位。

## 5. 页面交互

### 5.1 桌面端

保留左侧时间轴、右侧地图双栏结构。时间轴卡片增加拖拽把手：

- 拖动过程中显示插入位置，不产生持续花哨动画；
- 放下后调用纯函数更新顺序、自动重排时间并进入自动保存；
- 拖拽失败或放回原位不产生状态变化；
- 每张卡片仍有键盘可聚焦语义，不能只靠鼠标拖拽。

### 5.2 移动端与键盘等价操作

“编辑选中安排”面板提供：上移、下移、精确时间、停留时长、移动到同城日期、替换、删除。按钮最小高度 44px；不可用操作说明原因。移动端不依赖 HTML5 拖拽。

日期工具栏提供“复制当天”和“清空当天”：

- 复制先选择同城目标日并二次确认；
- 清空明确说明必去地点会保留，并二次确认；
- 没有同城目标日时禁用复制并解释原因。

### 5.3 地图与路线

- `PlaceEditor` 搜索当前日期城市，结果展示名称、地址和高德来源；
- 选择结果后才写入 `poi_id`、`address`、`citycode`、坐标和 `location_source: "amap"`；手工输入继续使用 `[0,0]` 和待定位状态；
- 地图只绘制 `location_source: "amap"` 且坐标有效的地点；
- 点击地图标记与点击时间轴互相同步；
- 只计算两个连续、已定位地点之间的路线，不跨过待定位地点；
- 路线结果展示距离、预计时间和折线；修改顺序、地点、日期或交通方式后立即清除旧结果；
- 公交缺少城市编码时提示用户重新搜索选择地点；
- 地图加载失败时保留完整时间轴和编辑能力。

## 6. 保存与撤销

### 6.1 自动保存

日程、预算或交通住宿的已确认变更进入统一 `current` 行程状态。没有打开中的编辑草稿时，变更停止 600ms 后调用现有 `onSave(current)`：

- 状态依次显示“未保存”→“正在保存…”→“已自动保存”；
- 新变更到来时取消旧定时器，只保存最新快照；
- 保存失败保留当前内存状态，显示“自动保存失败”，并保留“重试保存”按钮；
- 离页提醒只在仍有未保存变更、保存失败或编辑草稿未确认时出现；
- 手动保存按钮保留，作为立即保存和失败重试入口；
- 自动保存不得在初次加载、撤销到已保存快照或无实际变化时重复写入。

### 6.2 多步撤销

维护最多 20 个行程快照的撤销栈。每次用户完成一个可见操作时压入变更前快照；自动保存不新增撤销记录。撤销恢复完整行程并触发自动保存，连续撤销直到栈为空。页面切换行程时清空栈，不跨行程撤销。

## 7. 数据兼容与预算

- 不新增行程库版本；新能力复用现有 `ItineraryItem` 的可选高德字段，旧行程可以直接打开；
- 读取旧记录时，缺少 `location_source` 的坐标不得视为高德定位；
- 排序、移动和时间调整不改变地点费用；
- 删除继续扣减对应分类计划支出；
- 复制当天只对实际新增的地点增加计划支出，防止同名去重后重复计费；
- 保存仍通过 `travel:library:v2` 单记录原子写入，不拆分新的本地存储键。

## 8. 错误与边界行为

- 密钥缺失：状态接口明确返回不可用，手工编辑继续；
- Key 无权限、配额耗尽、域名白名单不匹配：显示高德返回失败的安全中文摘要，不回显 Key；
- 后端未启动或请求超时：地图区域降级，日程编辑和保存继续；
- 搜索快速重复提交：取消旧请求，只展示最新查询结果；
- 自动保存过程中继续编辑：旧结果不得覆盖较新的当前状态；
- 保存失败后继续编辑：失败状态保留，下一次自动保存或手动重试使用最新状态；
- 空日、仅一个地点、全部待定位地点、长地点名、同名地点、锁定地点和跨午夜时间都必须安全处理；
- 拖拽期间切换日期或工作区时取消拖拽状态，不误移动数据。

## 9. 测试与验收

### 9.1 纯函数测试

- 同日上移、下移、任意索引移动与原位无操作；
- 同城跨日移动成功，跨城市拒绝；
- 排序后时间按时长与 30 分钟缓冲重排，交通估算失效；
- 复制同城日去重并正确调整预算，清空保留锁定地点；
- 精确时间验证和日程诊断四类问题；
- 输入对象不被原地修改。

### 9.2 组件测试

- 拖拽和按钮排序产生相同结果；
- 移动端按钮禁用边界、二次确认、长名称换行；
- 自动保存防抖、最新快照、失败重试与离页保护；
- 20 步撤销上限与连续撤销；
- 搜索竞态、未配置、无结果、服务错误和选择真实地点；
- 地图只展示高德地点，路线修改后失效。

### 9.3 API 测试

- 状态接口不暴露 Web 服务 Key 和安全密钥；
- 搜索/路线参数校验、超时、供应商错误和限流；
- JS 样式代理只允许白名单路径并剥离回调参数；
- 实网冒烟只验证开发密钥可用，不把真实密钥写入测试代码或输出。

### 9.4 浏览器验收

- 桌面 `1280×800`：搜索真实地点、加入行程、地图标点、拖拽排序、自动重排、计算三种路线、自动保存、刷新恢复；
- 移动 `390×844`：使用上移/下移和跨日移动完成同等操作，无横向滚动或固定操作遮挡；
- 模拟地图服务中断后仍能手动编辑、保存和撤销；
- 控制台无密钥、hydration 错误、未处理 Promise 或框架错误层；
- 本阶段不部署。

## 10. 实施顺序

1. 安全配置并验证现有高德服务链路；
2. 用测试驱动扩展纯函数排序、移动、复制、清空与诊断；
3. 重构详情页保存状态为防抖自动保存和多步撤销；
4. 增加桌面拖拽与移动端等价操作；
5. 完善地图联动、路线失效、错误降级与响应式样式；
6. 运行前后端全量测试、生产构建和真实浏览器验收。
