# 旅行规划本地完善版设计

## 目标

在不接入外部服务、不部署线上环境的前提下，把现有演示站从“可浏览原型”完善为“本地可持续使用的产品闭环”。用户能够生成个性化演示行程、保存多份记录、再次打开、删除，并对当天安排做基础调整与撤销。

## 范围

- 新增统一的浏览器行程仓库，保存多份行程与当前选中行程。
- 新增“我的旅行”列表页，支持打开与删除。
- 演示规划器根据出发地、目的地、日期、天数、人数和预算生成个性化结果。
- 行程页支持保存反馈、安排提前或延后 30 分钟、删除非必去安排、撤销一次。
- 两个目的城市时支持交换城市顺序，并同步重排每日城市分组。
- 保留苏州、杭州演示地点库；其他城市明确显示“地点数据待接入”，不伪装真实 POI。

## 数据与组件边界

- `lib/travel-store.ts`：唯一负责 localStorage 序列化、兼容旧键、去重、选择和删除。
- `lib/personalize-itinerary.ts`：纯函数，将 `TripDraft` 转换为演示 `Itinerary`。
- `components/trips/trips-library.tsx`：我的旅行列表交互。
- `components/itinerary/itinerary-view.tsx`：持有当前可编辑副本与单步撤销快照，通过回调保存。
- `Itinerary` 增加 `travelers`，消除详情页写死人数的问题。

## 交互规则

- 生成成功即写入行程仓库，并选中该行程。
- 保存按钮写入仓库并显示非阻塞成功反馈。
- 必去地点不可删除；普通地点可删除。
- 每次调整前保留一个快照，撤销只恢复最近一步。
- 城市顺序调整仅在两个不同目的城市时开放；其他情况按钮禁用并给出原因。
- 空行程列表提供“创建第一份行程”入口。

## 视觉规则

继续使用 PRD 已确认的白色背景、深色正文、橙色强调、细灰边框和紧凑工具型布局。新增列表、调整条和反馈信息复用现有按钮、面板、时间轴组件，不引入新的视觉语言。

## 验证

- 纯函数和存储层使用 Vitest 测试。
- 列表、保存、调整、撤销使用 Testing Library 验证真实用户行为。
- 运行全量前端测试、后端测试、类型检查和静态生产构建。
- 使用本地浏览器验证桌面与手机核心流程，并与 PRD 效果图对照；不执行 Netlify 发布。
