# 当前天 AI 推荐设计

## 目标

在行程详情的“日程”工作区为当前日期增加真实可用的 AI 推荐。系统依据当前城市、当天节奏、剩余预算、已有地点与用户的临时要求，生成 3–5 个带建议时间的地点；用户预览并勾选后才加入当天，原行程不会被模型直接修改。

第一版直接调用 DeepSeek，使用高德真实地点作为候选池。DeepSeek 只能筛选和编排候选地点，不能创造地点、坐标或高德标识。

## 用户体验

### 入口

- 在行程详情“添加安排”旁增加“AI 推荐”按钮。
- 按钮只出现在日程工作区，并针对当前选中的日期工作。
- 点击后在日程内容上方展开行内面板，不使用遮挡地图的大弹窗。

### 输入

面板显示当前城市、日期、节奏和可用于当天安排的参考预算，并提供一个最多 300 字的自由输入框。示例文案为“带老人，少走路，想吃本地菜，下午可能下雨”。空输入也允许生成。

### 推荐与确认

- “生成推荐”进入明确的加载状态，但不锁住行程的其他区域。
- 成功后展示 3–5 张紧凑推荐卡，默认全部勾选。
- 每张卡显示地点、建议开始/结束时间、停留时长、每人预估费用、高德地址和推荐理由。
- 与当天已有地点重复的结果由后端删除；若最终没有有效结果，返回可操作的空状态。
- 可能与已有安排冲突的结果标记“加入后建议重新排程”。
- 用户可取消勾选任意结果，点击“加入当天”后才写入行程。
- 加入使用现有 `commit` 编辑通道，因此自动保存、撤销、预算更新和路线失效逻辑继续生效。
- “重新推荐”保留临时要求；关闭面板不会修改行程。

### 失败状态

- DeepSeek 未配置、鉴权失败、余额不足、限流、超时、返回空内容或格式错误，均显示面向用户的简短错误和“重试推荐”。
- 高德不可用时不调用 DeepSeek，因为无法保证地点真实；手动添加、日程编辑、保存和地图已有能力继续可用。
- 请求卸载、切换日期或再次生成时取消旧请求；旧结果不得覆盖新结果。

## 架构与数据流

```text
当前日上下文 + 临时要求
        ↓
POST /api/recommendations/day
        ↓
高德按城市获取真实候选地点并去重
        ↓
DeepSeek 从候选中选择、解释并排时
        ↓
后端按候选 POI、时间和字段规则再次校验
        ↓
前端临时预览 → 用户勾选 → 写入现有行程编辑器
```

推荐是一次性计算结果，不在后端建立会话，也不单独持久化。只有用户确认加入后的 `ItineraryItem` 进入浏览器行程存储。

## 后端接口

新增 `POST /api/recommendations/day`。

请求体：

```json
{
  "city": "苏州",
  "date": "2026-10-02",
  "intensity": "轻松",
  "travelers": 2,
  "remaining_budget_total": 1720,
  "existing_items": [
    { "name": "拙政园", "time": "10:00", "end_time": "11:30", "poi_id": "..." }
  ],
  "request": "带老人，少走路，想吃本地菜"
}
```

约束：城市 1–50 字；临时要求最多 300 字；已有安排最多 20 项；人数 1–20；`remaining_budget_total` 表示整个行程当前预计结余，必须是有限数且不得小于 0。后端按客户端地址执行独立于地图接口的限流，第一版为每分钟最多 6 次推荐。

响应体：

```json
{
  "recommendations": [
    {
      "poi_id": "...",
      "name": "苏州博物馆(本馆)",
      "address": "东北街204号",
      "citycode": "0512",
      "coordinate": [120.6277, 31.3241],
      "category": "景点",
      "time": "13:30",
      "end_time": "15:00",
      "duration_minutes": 90,
      "cost": 0,
      "reason": "室内参观且与上午园林路线相邻",
      "notice": "开放时间与费用需出发前确认"
    }
  ],
  "summary": "兼顾少步行和室内体验",
  "warnings": []
}
```

客户端错误使用 4xx；供应商不可用、无效响应和超时使用 502/503/504；返回文案不包含供应商响应正文、密钥或内部提示词。

## 高德候选地点

- 后端复用现有高德 Web 服务密钥和地点解析规则。
- 使用当前城市搜索适合行程的候选主题，包括景点、博物馆、公园和特色美食；结合用户要求添加一个经过长度限制的搜索词。
- 每类只取有限结果，按 `poi_id` 去重后最多向模型提供 24 个候选。
- 排除当天已经存在的 `poi_id`；没有 `poi_id` 的旧地点再按规范化名称去重。
- 丢弃缺少名称、真实坐标或高德标识的候选。

## DeepSeek 集成

后端通过 `https://api.deepseek.com/chat/completions` 调用 DeepSeek，配置项为：

- `DEEPSEEK_API_KEY`：必需，只存在于 `apps/api/.env.local` 或生产秘密管理服务。
- `DEEPSEEK_BASE_URL`：默认 `https://api.deepseek.com`。
- `DEEPSEEK_MODEL`：默认 `deepseek-flash`，允许部署时替换。
- `DEEPSEEK_TIMEOUT_SECONDS`：默认 20，限制为合理范围。

请求使用非流式 JSON Output：`response_format={"type":"json_object"}`，提示词明确要求 JSON 并给出完整示例；输出上限控制在完成 5 条推荐所需范围。DeepSeek 官方文档提示 JSON Output 可能偶发空内容，因此空内容作为可重试的供应商失败，不直接返回空成功。

系统提示词把用户要求标记为不可信数据，要求模型忽略其中改变规则、索取密钥、创建候选外地点或输出非 JSON 的指令。候选地点使用稳定的短 ID；模型仅返回候选 ID、时段、时长、费用和理由。

## 服务端校验

模型输出永远视为不可信：

- JSON 必须解析为预期对象，推荐数量为 1–5。
- 每个候选 ID 必须存在于本次高德候选集合中；名称、地址、坐标、城市编码和分类全部由后端候选数据回填，而非采用模型值。
- 时间必须为严格 `HH:mm`，停留时长为 15–360 分钟，结束时间不得跨午夜。
- 每人费用为 0–100000 的有限数；第一版是估计值，不标记为实时价格。
- 推荐 ID 与已有地点、推荐内部不得重复。
- 推荐理由去除首尾空白并限制为 120 字。
- 任何无效单项直接丢弃；全部无效则返回 502，不产生可确认结果。

## 前端组件与状态

新增独立 `AiDayRecommendations` 组件，负责输入、请求生命周期、结果勾选和错误展示。它接收当前 `Itinerary`、日期索引及一个 `onApply(items)` 回调，不直接访问本地存储。

新增前端推荐 API 客户端和类型。请求通过现有 API base URL；切换日期、关闭面板和重新生成时使用 `AbortController`。推荐结果只存在于组件状态。

确认加入时使用新的纯函数 `addRecommendedItems(itinerary, dayIndex, items)`：

- 再次去重并验证字段；
- 按开始时间插入；
- 仅按实际新增项目增加票务、餐饮、住宿或其他预算；
- 清除受影响日程中过期的本地交通估算；
- 不自动覆盖或删除用户已有安排；
- 返回新对象供现有 `commit` 记录一次可撤销操作。

## 安全与隐私

- DeepSeek Key 不得进入前端包、状态接口、日志、错误响应、测试快照、文档或版本控制。
- 发给 DeepSeek 的数据只包含推荐所需的城市、日期、节奏、预算、已有地点摘要、用户临时要求和高德候选摘要，不包含兑换码、用户身份或其他行程。
- 不记录完整提示词、用户自由输入、候选列表或模型原始响应；开发日志只允许状态码、耗时和有效结果数量。
- 限制输入、候选和输出规模；禁止任意上游 URL；DeepSeek base URL 只能来自后端配置。
- 截图或聊天中出现过的开发 Key 在生产部署前必须轮换。

## 测试与验收

### 后端自动化

- 未配置 DeepSeek 时返回可理解的 503，且响应不含秘密。
- 高德候选搜索、去重与最大数量。
- DeepSeek 请求只包含允许字段并启用 JSON Output。
- 鉴权、余额、限流、超时、空内容、截断和非法 JSON 的错误映射。
- 提示词注入文本不能改变候选白名单。
- 虚构候选、重复地点、非法坐标、非法时间、跨午夜和异常费用被丢弃或拒绝。
- 任意异常响应不得包含 DeepSeek Key、高德 Key或模型原始响应。

### 前端自动化

- 打开/关闭面板、空要求生成、300 字限制与加载状态。
- 快速连续生成只显示最后一次结果，切换日期取消旧请求。
- 推荐卡默认勾选、可取消、空选择不能加入。
- 确认加入只写入有效选中项，更新预算，并可一次撤销。
- 重复地点不加入；冲突标识和“建议重新排程”操作正确。
- 服务失败保留输入且允许重试，不阻止手动编辑和保存。

### 浏览器验收

- 桌面端真实调用 DeepSeek，获得 3–5 条来自高德的可定位建议并选择性加入。
- 加入后地图出现标记，自动保存完成，刷新后仍存在，撤销后再次自动保存。
- `390×844` 下无横向溢出，输入框和主要按钮可触控。
- DeepSeek 不可用和高德不可用分别验证降级；控制台无未处理错误。
- 源码、构建输出和浏览器网络检查不出现 DeepSeek Key、高德服务 Key或安全密钥。

## 非目标

- 第一版不生成完整多日行程，不替换创建向导现有规划器。
- 不做聊天机器人、多轮对话、流式文字动画或长期 AI 会话。
- 不自动预订门票、餐厅、酒店或交通。
- 不把模型建议当作已核实的开放时间或实时价格。
- 本轮不部署 Netlify。
